TARA · RLHF · demo 01

The same loop, a new agent

Tab 1: last week's agent–environment loop, stepped arrow by arrow, for CartPole and for GPT-2. Tab 2: one GPT-2 episode, token by token, with its reward and value.

CartPole uses the real CartPole physics with a hand-made policy. GPT-2 mode uses the toy next-token table from tab 2. Same loop, same arrows.

1 · The loop from week 1

The agent reads the state, its policy gives probabilities, it samples an action, the environment answers with a reward and the next state. Press Step to walk one arrow at a time.

2 · CartPole, as you know it

State = 4 numbers. Two actions, two probabilities. The physics moves the cart (we never write it down). +1 every step until the pole falls.

3 · Now press "GPT-2 · today"

State = the text so far. ~50,000 actions; we sample from the top 10. The environment just glues the token on.

4 · What changed

The transition is exact (no physics). The reward is 0, 0, 0 … then one number for the finished text. Every episode has the same length: 12 here, gen_len = 30 in the notebook.

5 · What did not

The loop, π(a | s), and sampling. Last week's recipe applies unchanged: play, score, nudge.

Next-token probabilities π(a | s): top 10

Toy model: a hand-made table of next-token probabilities (a "bigram" model), not real GPT-2. The value row is the exact expected final reward under this toy policy — what a perfectly trained value head would output.

1 · The state is the whole row

The agent sees every token so far: the prompt plus everything it has written. Adding a token makes the next state: s_{t+1} = [s_t a_t].

The prompt (grey) is the same in every episode: prefix = "This is", 3 tokens with the BOS token.

2 · An action is one token

The bars are the policy π(a | s): the model's probability for each possible next token. Only the top 10 are allowed (top_k = 10); one is sampled (coral).

Drag temperature: low = sharper, high = flatter (temperature = 1.0 in the notebook).

3 · Fixed-length episodes

Every episode is exactly gen_len new tokens (12 here, 30 in the notebook). Generation never stops early: stop_at_eos=False.

4 · Reward: 0, 0, 0 … then one number

Nothing is scored until the text is finished. Then reward_fn reads the whole text and counts the periods. " U.S." is worth 2, "..." is worth 3.

Press Finish episode to see it.

5 · The value: a forecast at every position

The V row is the critic's job: "from here, how many periods will this text end with?" It is defined after every token, even though the reward only arrives at the end.

Watch V jump when a period-heavy token is written.

6 · Why there is no γ

One reward, always after the same number of steps. Discounting would multiply every return by the same constant, which changes nothing. So the notebook removes gamma and gae_lambda.

7 · The question for Part 5

The reward is one number for the whole text. Which tokens deserve the credit? Hint: look at where V moved. Tick show advantages to peek.
