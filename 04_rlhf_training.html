Train a tiny "GPT" to write periods

A toy model writes "This is" + 4 chunks. Reward = number of periods. Objective = reward − kl_coef × KL to the frozen original, like the notebook. Text pieces are borrowed from the notebook's real samples.

1 · The toy model

Each chunk is picked from 5 options. The outline bars are the frozen original's probabilities: most likely are plain phrases, least likely the "Not......" junk.

2 · One phase

Sample 32 texts → count periods → normalise over the batch → push up the chunks used in above-average texts, minus kl_coef × the KL gradient. (A simplified PPO step, no critic.)

3 · kl_coef = 0

Press 0, Reset, Run. Reward shoots up, KL shoots up, and the text turns into period spam like "Not.........". The ref log-prob column falls: the original would never write this. In the notebook: 1.3 → 20 in 30 phases.

4 · kl_coef = 2.5

Press 2.5, Reset, Run. Reward rises a little, KL stays small. The chunks that grow are the ones the original already liked: "a rush transcript.", "Copy may not be in its final form.", "we turn now to the U.S." Periods that cost little KL. In the notebook this narrowed into one favourite text: mode collapse.

5 · kl_coef = 10

The penalty is so strong the model barely moves from the original.

6 · RL only reinforces what it tries

Run kl_coef = 0 a few times. Each run can end somewhere different (e.g. "a.k.a. A-man." instead of the junk in one chunk): whatever got sampled and rewarded first wins.

1 · Where long training ends up

For each penalty weight, the solid bars show where training settles if you run it long enough. The dashed outline is the original GPT-2.

2 · Slide the weight down

Small weight: the reward dominates. The highest-reward chunk wins even if the original almost never wrote it: junk.

3 · Slide the weight up

Large weight: the result stays at the original GPT-2. Nothing changes.

4 · In between

Options that are likely under the original AND score well win. That is why the rush transcript appears.

This toy uses raw period counts, so its weight is not on the same scale as the notebook's kl_coef.
