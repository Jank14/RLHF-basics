The ranking becomes pairs (winner > loser)

Reward model scores R(prompt, answer)

1 · The model writes several answers

For one prompt, the SFT model writes K answers (InstructGPT: 4 to 9). Nobody has to write an answer.

2 · A person ranks them

Ranking is much quicker than writing. Try changing the order.

3 · Ranking → pairs

K answers give K(K−1)/2 pairs. 4 answers → 6 pairs, each "this one beat that one".

4 · Train the scorer

The reward model gives each answer one number. Loss per pair: −log σ(Rwinner − Rloser). Press Train: scores spread out in your ranking's order and the loss falls.

5 · Use it as the reward

Once trained, it scores any new answer with no person in the loop. That number is the reward PPO maximises. Today's notebook skips this step (tab 2).

Four finished texts from one batch (edit them)

Raw reward → normalised over the batch

1 · No humans, no reward model

The notebook uses a fixed function as the reward. It reads the finished 30-token text and returns one number.

2 · Count the periods

reward_fn_char_count: "This is a test." → 1, "......" → 6. Type more periods and watch the raw reward change.

3 · Normalise over the batch

normalize_reward: (r − batch mean) / batch std. Above-average texts become positive, below-average negative, whatever the raw scale.

4 · A jackpot it never finds

GPT-2 has one token made of 64 periods (id 23193). It would score 64, but GPT-2 never samples it, so it is never rewarded and never learned: RL only learns from what it tries.
